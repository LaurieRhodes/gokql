## How these pages are made

The operator, function, aggregation, plugin and command pages, and
`support.json`, are generated by the test suite. `catalog.json` lists
every entry of Microsoft's KQL documentation (extracted from its table
of contents by `tools/gen-reference/extract_catalog.py`); the test
`TestReferenceDocs` probes this engine for each entry, and the "gokql"
column says whether it is accepted. `notes.json` holds the notes
beside an entry: where gokql differs, or why something is missing. The
test fails when a page no longer matches the engine:

```bash
go test ./pkg/engine -run TestReferenceDocs -update-reference
```

The CLI and configuration pages are written by hand, with tests that
fail when a flag is undocumented or the configuration template
changes.

Descriptions on the generated pages are the first sentence of each
entry's page in Microsoft's
[KQL documentation](https://learn.microsoft.com/kusto/query/),
licensed CC BY 4.0, and each name links to that page.
