# Parity Backlog — re-enumeration of 2026-10-22

The active work queue for KQL parity. Built by running every name and
form below through the CLI (`print`, `summarize`, `evaluate`, and
operator probes over a `datatable`) and recording only failures whose
error names the feature as unknown or unparsed. Reference lists:
Microsoft's scalar-function and aggregation-function index pages.

The function-name backlogs (`scalar_function_backlog.md`,
`timeseries_backlog.md`) measured names only. Most of what follows is
operator options, window functions, literal syntax and plugins, which
those lists never covered; `kql_coverage.md`'s "0 known gaps" for
tabular operators held for operator names, not for their options.

Signatures (argument and return types, optional parameters) are
checked against Microsoft's own KQL front end, `Kusto.Language`
(npm `@kusto/language-service-next`, `Kusto.Language.Bridge.js`),
where the reference pages are silent.

Priority is by frequency in Sentinel analytics rules, hunting queries
and ASIM parsers, which is this engine's main query population.

## P2 — real but less frequent

Since 2026-10-23 the aim for the items ADX does not specify is a
usable tool, not bit-exact agreement. Implemented that way (each file's
header says what was pinned and what is an approximation):

- `series_periods_detect`, `series_periods_validate`, and seasonality -1
  of `series_decompose*` and `series_seasonal`: spectral-peak gate plus
  circular-autocorrelation score. The top period agrees with ADX on the
  probes (the reference's 14; 168 and 24 on weekly hourly data; the
  forecast with test points detects ADX's 144); scores differ by a few
  hundredths; with mixed tones gokql may list a second real period
  ADX omits.
- `diffpatterns`: closed-itemset contrast, ranked by |PercentA -
  PercentB| with a redundancy filter. On the StormEvents reference
  every ADX segment appears with the same counts, plus three further
  genuine differences.
- `reduce`: Drain-style template clustering with ADX's output shape;
  the reference examples give ADX's patterns. Suited to log/alert lines;
  free text with varying word counts mostly lands in "others".
- `autocluster` on large real inputs, `funnel_sequence` prev/next edge
  cases: approximations, as noted in their files.

Not done:

- The `python` plugin (plotly_graph_fl): judged not worth it.

Done 2026-10-23: GQL and openCypher (docs/gql.md), translated to
graph-match. The emulator (2025.07.06) rejects much of its own
documented GQL (LET, FOR, NEXT, FILTER, element WHERE) and gets
OPTIONAL MATCH, CASE and abs() wrong; gokql follows the documented
results and the GQL standard there.

short to rewrite. The emulator license forbids benchmarking.
